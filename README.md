# FF 스포츠 중계 v0.4.16

## v0.4.16 변경사항

- 일부 FF 플러그인 로더가 sys.modules에 문자열이 아닌 모듈 객체를 키로 보관하는 환경에서도 SportsGuide Playwright 격리 로직이 안전하게 동작하도록 보강했습니다.
- ff_chzzk.source_chzzk 같은 외부 플러그인 모듈 객체가 sys.modules 키로 존재해도 .startswith()를 호출하지 않고 그대로 건너뜁니다.
- 해당 충돌 상황을 인위적으로 재현해 0.4.15의 AttributeError를 확인한 뒤, 수정 후 같은 조건에서 Playwright 1.58.0 및 Chromium 1208 실행까지 정상 동작하는 것을 검증했습니다.

## v0.4.15 변경사항

- 첫 설치 시 Playwright Python, Chromium 다운로드, Chromium 실행 점검을 FF 요청/주기 갱신 프로세스에서 분리해 별도 백그라운드 프로세스로 준비합니다.
- 브라우저 준비 중 B/C 갱신 요청은 즉시 준비 중 상태로 반환하고 기존 B/C 캐시와 Alive 목록을 유지하므로 FF 전체 응답을 막지 않습니다.
- Chromium 실행 테스트에서 OS 공유 라이브러리 부족이 확인된 경우에만 playwright install-deps chromium을 같은 백그라운드 준비 프로세스에서 1회 수행한 뒤 다시 실행 테스트합니다.
- 백그라운드 준비 작업은 중복 실행되지 않도록 PID/락을 사용하고 낮은 프로세스 우선순위로 실행합니다.
- B/C 화면에서 브라우저 준비 중 응답을 받으면 화면을 다시 로드하지 않고 준비 중 안내만 표시합니다.
- 첫 설치 시뮬레이션에서 Playwright/Chromium이 전혀 없는 상태로 시작해 B 갱신 호출이 0.001초 내 반환되고, 설치가 진행되는 동안 M3U가 계속 HTTP 200으로 응답하는 것을 확인했습니다.
- OS 의존성 부족 분기를 강제로 재현하여 install-deps 실행 중에도 M3U가 계속 HTTP 200으로 응답하고 최종 ready 상태로 전환되는 것을 확인했습니다.

## v0.4.14 변경사항

- B/C 화면에서 캐시가 오래됐거나 비어 있을 때 0.5초 후 자동 갱신하던 동작을 제거했습니다. 이제 화면 진입만으로 Chromium 수집이 반복되지 않으며, 화면의 갱신 버튼을 눌렀을 때만 수동 갱신합니다.
- 서버의 설정된 A/B/C 주기 갱신은 기존대로 유지합니다.
- Linux FF 환경에서는 SportsGuide 전용 playwright==1.58.0을 /data/db/ff_sportsguide/python에 고정하여 FF 본체나 다른 플러그인의 Playwright 버전에 영향받지 않도록 했습니다. Chromium은 대응 버전을 /data/browsers에서 사용합니다.
- B/C 갱신 실패 시 이전 정상 캐시까지 사용할 수 없는 소스가 하나라도 생기면 부분 목록으로 Alive를 덮어쓰지 않고 마지막 정상 통합 목록과 기존 Alive를 보존합니다.
- Chromium 실행 실패 진단에서 공유 라이브러리 부족 문구를 추가 감지하고, 긴 브라우저 오류는 앞부분과 끝부분을 함께 남겨 실제 원인이 로그에서 잘리지 않도록 했습니다.
- alive.yaml.bak-sportsguide-YYYYMMDD 백업은 최근 7개만 유지하고 그보다 오래된 날짜 백업은 자동 정리합니다. 날짜 형식이 아닌 수동/기타 백업은 건드리지 않습니다.
- zelits1에서 전용 Playwright 1.58.0 + Chromium 1208 실행, B/C 스냅샷 갱신, A/B/C 통합 갱신, M3U HTTP 200 응답을 확인했습니다.

## v0.4.13 변경사항

- B/C 목록 갱신이 실패해도 이전 정상 캐시가 있으면 해당 소스만 캐시 모드로 전환하고 A/B/C 전체 갱신은 계속 진행합니다.
- 정상 갱신의 15분 신선도 기준은 유지하며, 장애 복구용 이전 캐시는 명시적인 실패 상황에서만 최대 6시간까지 제한적으로 사용합니다.
- 이전 캐시조차 없는 소스는 해당 소스만 제외하고 사용 가능한 다른 소스로 통합 목록과 중복 제거를 계속 수행합니다. 모든 소스를 사용할 수 없으면 마지막 정상 통합 목록을 보존합니다.
- Playwright 번들 Chromium의 자동 설치/OS 의존성 복구 후에도 실행이 실패하면 컨테이너에 설치된 `chromium`, `chromium-browser`, `google-chrome` 계열 실행 파일을 자동 탐색하여 한 번 더 시도합니다.
- Chromium 최종 실행 실패 시 공통 오류 문구로 숨기지 않고 실제 마지막 오류 내용을 반환하고 `/data/db/ff_sportsguide/browser_last_error.json`에도 진단 정보를 저장합니다.
- `/api/m3u` 생성 중 특정 경기의 키나 재생 URL이 잘못되어도 해당 경기만 제외하고 나머지 M3U를 HTTP 200으로 계속 제공합니다. 통합 캐시가 없어도 최소 `#EXTM3U` 응답을 반환합니다.
- Alive 동기화도 특정 경기의 재생 URL 생성 실패를 항목 단위로 격리하며, 전체 항목이 실패한 경우에는 기존 Alive 목록을 보존합니다.
- 강제 Chromium 실패, B/C 이전 캐시 fallback, 15분 정상 만료/6시간 장애 fallback, 시스템 Chromium 대체 경로, 잘못된 M3U 항목 주입 테스트를 통과했습니다.

## v0.4.12 변경사항

- Alive와 `/api/m3u`가 같은 `채널 표시 접두어` 설정을 사용하도록 변경했습니다.
- 기본 접두어는 `Sports`이며 `[Sports] [리그] 경기명` 형식으로 표시합니다.
- 접두어를 비우면 `[리그] 경기명`만 표시하며, 사용자가 원하는 값으로 자유롭게 변경할 수 있습니다.
- 접두어 변경 시 Alive 연동이 활성화되어 있으면 채널명도 즉시 다시 동기화합니다.
- 설정 화면의 공급자 주소를 `메인 URL` 하나로 통합했습니다. 도메인 루트만 변경하면 A/B/C가 같은 새 도메인을 다음 갱신부터 사용합니다.
- 사용자는 `메인 URL`만 설정합니다. A/B/C 페이지 및 재생 연동 기본값은 플러그인에 포함되어 플러그인 업데이트와 함께 갱신됩니다.
- 서로 다른 소스의 종목/category 값이 달라도 동일 경기 제목을 우선으로 판정하는 중복 제거 로직을 유지해 NFL 등 오분류 소스의 중복 노출을 방지합니다.

## v0.4.11 변경사항

- `/ff_sportsguide/api/m3u`가 A/B/C 통합 목록을 사용하며 Alive와 동일한 중복 제거 및 우선 소스 선택 결과를 반영합니다.
- M3U 표시는 `[리그] 경기명`, Alive 표시는 `[Sports] [리그] 경기명` 형식으로 간소화했습니다. 리그가 없으면 경기명만 표시합니다.
- `basket`/`volley` 종목 코드를 각각 농구/배구로 정규화했습니다.
- B/C가 BWF 경기를 Tennis로 잘못 분류하는 경우 BWF 리그를 기준으로 배드민턴으로 보정합니다.
- BWF의 `Court 1`/`Court 2`처럼 서로 다른 코트는 분리하고, 같은 코트의 A/B/C 소스만 하나의 경기로 통합하도록 중복 판정을 보강했습니다.
- SportsGuide가 `alive.yaml`을 실제 변경한 경우 Alive의 `channel_list_updated_at`을 만료시켜 별도 수동 갱신 없이 다음 채널/M3U 요청에서 새 목록을 읽도록 했습니다. 변경 없음, Dry-run, 저장 실패 시에는 Alive 캐시를 건드리지 않습니다.
- Alive 캐시 무효화가 실패하면 최대 3회 재시도하고, 실패 상태를 남겨 다음 동기화에서 다시 시도합니다.
- Playwright Python 패키지와 Chromium 자동 설치에 더해, Chromium 실행 시 OS 의존성 부족 오류를 감지하면 `playwright install-deps chromium`을 자동 실행한 뒤 재시도합니다.
- B/C는 같은 Playwright 준비 로직을 공유하며, 첫 설치가 오래 걸리는 환경을 위해 수동 갱신 요청의 최대 대기시간을 16분으로 늘렸습니다. 평소 갱신 시간과 자동 갱신 주기에는 영향을 주지 않습니다.
- B/C 갱신에는 기존 실행 락을 유지하여 같은 소스의 중복 갱신이 동시에 실행되지 않도록 했습니다.
- 중복 판정은 종목값에 의존하지 않고 경기명을 1순위로 사용하도록 변경했습니다. 완전 동일한 경기명은 종목 분류가 달라도 통합하며, 표기 차이가 있는 경우 리그/시간을 보조조건으로 사용합니다.
- `NFL`처럼 A/B/C에서 같은 경기가 서로 다른 종목값으로 내려오는 경우에도 제목 유사도로 통합되며, BWF Court 번호가 다른 경기는 계속 분리합니다.

## v0.4.8 변경사항

- 자동 설치한 Python 패키지는 `/data/db/ff_sportsguide/python`, Chromium은 `/data/browsers`에 저장하여 FF 컨테이너 재생성 후에도 유지할 수 있도록 했습니다.
- Playwright/Chromium 설치 작업에 파일 락을 적용하여 B/C 동시 갱신 시 중복 설치를 방지합니다.
- Playwright가 없는 환경을 별도 경로로 재현하여 Python 패키지 자동 설치를 검증했고 Chromium 설치 명령도 정상 동작을 확인했습니다.
- B 채널 상단 안내를 현재 방송 중(ING) 경기 표시 내용만 남기도록 정리했습니다.
- C 채널 상단 안내를 현재 방송 중 경기와 Proxy 사용 내용만 남기도록 정리했습니다.

## v0.4.6 변경사항

- Alive 연동 화면의 A/B/C 콤보박스는 삭제하지 않고 **우선 중계 소스** 선택으로 사용합니다.
- 같은 경기가 여러 소스에 있으면 선택한 우선 소스를 사용하고, 없으면 사용 가능한 다른 소스를 자동 선택합니다.

- C Alive 재생을 위한 안정 주소 `c_live.m3u8?id=...`를 추가했습니다.
- A/B/C 중 하나라도 목록 갱신에 실패하거나 오래된 경우 기존 Alive 통합 채널을 보존합니다.
- C 원본 목록의 전체 행 수를 함께 저장하여 0건 상태에서도 잘못된 삭제를 방지합니다.
- 플러그인은 기존 원칙대로 `channel_group`을 자동 추가/삭제/수정하지 않습니다.

## v0.4.5 주요 변경사항

- 중계 C를 추가했습니다.
- C는 현재 방송 중인 경기만 수집하고 예정 경기는 표시하거나 저장하지 않습니다.
- C 목록 수집은 Playwright Chromium과 Proxy를 사용합니다.
- C 재생은 FF 전용 HLS relay를 거쳐 Proxy + Referer 조건으로 재생합니다.
- A/B/C 경기명 앞에 `[종목]`을 표시합니다.
- B/C는 원본 사이트의 category 값을 사용합니다.
- A는 원본 사이트 경기 행의 `data-category` 값을 읽어 종목명으로 변환합니다.
- A/B/C 재생창 제목도 같은 `[종목] 경기명` 형식을 사용합니다.

## 설치

1. FF의 플러그인 설치 화면에서 아래 Git 주소를 입력해 설치합니다.

   `https://github.com/zeliit/ff_sportsguide`

2. FF를 재시작합니다.
3. `스포츠 중계 현황` 설정에서 전달받은 **메인 URL**을 입력하고 저장합니다.
4. 메인 URL을 처음 저장하거나 변경하면 경기 목록 갱신을 백그라운드에서 시작합니다.

GitHub Release나 별도 ZIP 파일은 필요하지 않습니다. FF는 저장소를 직접 clone하여 설치합니다.

## 배포

디스코드 등에서 신규 사용자에게는 **Git 주소와 메인 URL 두 가지만** 전달하면 됩니다. Git 저장소로 플러그인을 설치한 뒤 설정 화면에서 메인 URL을 저장하면 A/B/C에 공통 적용됩니다. Proxy가 없는 환경에서는 A/B로 먼저 동작하며, C는 Proxy가 설정된 환경에서 자동으로 통합됩니다.

## 설정

- **메인 URL**: 도메인 루트 주소 하나만 입력합니다. A/B/C의 페이지 경로는 내부 설정을 이용해 자동으로 조합합니다.
- 메인 도메인만 변경되고 페이지 구조가 동일한 경우에는 이 값만 바꿔 저장하면 다음 A/B/C 갱신부터 새 도메인을 사용합니다. FF 재시작은 필요하지 않습니다.
- 채널 표시 접두어는 Alive와 M3U에 공통 적용되며 기본값은 `Sports`입니다. 빈칸으로 저장하면 접두어를 표시하지 않습니다.
- 사용자는 `메인 URL`만 입력합니다. A/B/C 페이지 및 재생 연동 기본값은 플러그인에 포함되어 함께 업데이트됩니다.
- `/data/db/ff_sportsguide/provider.json`에는 메인 URL만 저장되며 직접 편집할 필요가 없습니다.

## 런타임 데이터

- FF 설정 DB `ff_sportsguide.db`는 FF 규칙대로 `/data/db`에 유지합니다.
- SportsGuide 전용 런타임 설정, 캐시, 서명키와 잠금 파일은 `/data/db/ff_sportsguide/` 아래에 보관합니다.
- 플러그인 소스 디렉터리에는 런타임 데이터를 저장하지 않습니다.

## 채널

- A: 원본 `data-category`를 이용해 종목을 표시합니다.
- B: 원본 category 값을 이용해 종목을 표시합니다.
- C: 현재 방송 중인 `liveNow` 경기만 표시합니다.
- A/B/C 개별 탭은 원본 확인과 수동 갱신용으로 유지합니다.
- Alive에서는 세 소스를 통합하여 사용합니다.

## Alive 통합 연동

설정된 갱신 주기마다 활성 소스를 갱신한 뒤 방송 중 경기만 통합합니다. Proxy가 없으면 A/B를 사용하고, C용 목록 Proxy가 설정되어 있으면 A/B/C를 함께 사용합니다.

같은 경기는 하나만 Alive에 등록하며, Alive 연동 화면의 **우선 중계 소스 A/B/C** 설정을 먼저 사용합니다. 우선 소스에 해당 경기가 없으면 사용 가능한 다른 소스로 자동 대체합니다.

Alive 채널명 형식:

`[Sports] [테니스] 선수A vs 선수B`

통합 관리 키는 `sgu_...` 형식입니다. SportsGuide가 만든 통합 관리 키만 추가/갱신/삭제하며, SOOP KBO나 다른 플러그인 채널, 사용자가 직접 만든 `fix_url` 항목은 보존합니다.

활성 소스 중 하나라도 수집 실패, 오래된 캐시, 비정상 원본 목록으로 판단되면 기존 Alive 통합 채널을 삭제하지 않습니다.

### Alive 그룹

SportsGuide는 안전을 위해 `channel_group`을 자동 수정하지 않습니다.

Alive에서 Sports를 별도 그룹으로 보고 싶다면 사용자가 한 번 다음 그룹을 추가해야 합니다.

```yaml
- name: 05.2 Sports
  type: pattern
  pattern: '^\\[Sports\\]'
```

이 그룹은 일반적인 `^\\[.*?\\]` 같은 넓은 OTT 패턴보다 위에 두는 것을 권장합니다.

## Proxy

- 목록 조회 Proxy: A/B/C 원본 목록 수집에 사용합니다. C 목록 조회에는 Proxy가 필요합니다.
- A 재생: 재생 Proxy 설정에 따라 직접 재생 또는 FF relay를 사용합니다.
- B 재생: 필요한 헤더 처리를 위해 FF relay를 사용합니다.
- C 재생: 원본 특성상 FF relay와 설정된 Proxy를 항상 사용합니다.

## Playwright / Chromium

B/C 채널 목록 갱신에 Playwright Chromium을 사용합니다.

Playwright Python 패키지가 없으면 첫 B/C 갱신 시 `playwright==1.58.0`을 `/data/db/ff_sportsguide/python`에 자동 설치합니다. Chromium 실행 파일이 없으면 이어서 `/data/browsers`에 자동 설치합니다. `/data`를 사용하므로 FF 컨테이너를 다시 만들어도 설치 파일을 유지할 수 있습니다.

첫 설치 시에는 다운로드 때문에 평소보다 갱신 시간이 오래 걸릴 수 있습니다. Chromium 바이너리와 Python 패키지는 배포 ZIP에 포함하지 않습니다.
